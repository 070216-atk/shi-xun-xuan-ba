# 学生实训室进组选拔系统 PRD

> 版本：v0.1（初稿，供小组评审）
> 日期：2026-11-09
> 依据：《学生实训室进组选拔流程》流程图（双向选择 · 分轮录取 · 统筹调剂）

---

## 项目概述

面向学院"AI+PBL 项目实训"进组选拔的线上化系统，把原本线下/表格完成的 8 步选拔流程搬到线上：

**集中宣讲 → 实训室开放日 → 意向填报 → 导师初选与面试考核 → 拟录取与学生确认 → 分轮补录（第二、三轮）→ 统筹调剂录取 → 结果公示与正式入组**

系统核心解决三个问题：
1. **双向选择**：学生填意向、导师做初选与面试，双方意愿都要匹配；
2. **分轮录取**：首轮 + 两轮补录，每轮有明确的时间窗口和顺位递补规则；
3. **统筹调剂**：末轮剩余名额进入全院调剂池，按"室内调剂 → 跨室调剂 → 约谈安置"三级优先级兜底，保证人人有组。

## 目标用户

| 角色 | 说明 | 主要诉求 |
|------|------|----------|
| 学生 | 参加选拔的本科生 | 查看实训室信息、填报意向、确认录取、参加补录 |
| 导师 | 各实训室指导教师 | 查看报名学生、录入面试评价、确定拟录取/递补/调剂候选名单 |
| 实训室管理员 | 每个实训室 1 名（可由导师兼任） | 维护本室项目介绍与名额、组织面试、管理本室名单 |
| 学院管理员 | 教务/学院负责人 | 配置流程时间轴、发布剩余名额、执行统筹调剂、公示结果 |

## 核心功能

### F1 信息发布与浏览（对应流程 1、2）
- 学院发布宣讲通知、各实训室项目方向、招录名额、培养安排与考核要求；
- 开放日安排展示（时间、地点、联系人）；
- 学生无需登录即可浏览公开信息。

### F2 意向填报（对应流程 3）
- 学生在窗口期内（如 11月2日 08:00–12:00）填报 **最多 3 个平行导师意向，不分先后**；
- 同时勾选两项独立选项：是否服从**实训室内部调剂**、是否服从**全院跨实训室调剂**；
- 窗口关闭后锁定，不可修改；截止前可反复修改。

### F3 导师初选与面试考核（对应流程 4）
- 以**实训室为单位**统一组织面试；无论报名是否满额，**所有报名学生均参加面试**；
- 导师按四个维度录入评价：学习态度、逻辑思维、编程基础、时间投入（建议 1–5 分 + 评语）；
- 实训室产出三份名单：**拟录取名单、递补名单（含顺位）、内部调剂候选名单**。

### F4 拟录取与学生确认（对应流程 5）
- 学生仅收到 **1 个**拟录取意向 → 系统**自动确认**；
- 收到 **2 个及以上** → 学生在窗口期内（如 11月4日 08:00–12:00）**自主选择唯一去向**；
- **逾期未确认视为放弃**，空出名额按递补名单顺位自动递补（递补后仍需学生确认）。

### F5 分轮补录（对应流程 6）
- 学院公布各室剩余名额，未录取学生重新填报志愿；
- 实训室统一组织面试、双向确认与顺位递补；
- 依次完成**第二轮、第三轮**补录，每轮复用 F2–F4 的逻辑（轮次编号区分）。

### F6 统筹调剂录取（对应流程 7）
- 三轮后剩余名额全部纳入**全院调剂池**；
- 按优先级依次执行：
  1. 实训室**内部调剂**（从本室调剂候选名单中安排）；
  2. 全院**跨实训室调剂**（限勾选服从的学生）；
  3. **约谈未服从调剂学生**并做最终统筹安置（线下约谈，系统记录结果）；
- 学院管理员操作，每一步留痕可查。

### F7 结果公示与正式入组（对应流程 8）
- 学院汇总最终录取名单并公示，**公示期 1 天**；
- 公示无异议后状态变为"正式入组"，学生可查看所属实训室与导师。

### F8 流程引擎与通知（贯穿全流程）
- 学院管理员可配置每个阶段的起止时间，系统按时间窗口自动开放/关闭对应操作；
- 关键节点站内通知：填报开启/即将截止、收到拟录取、确认倒计时、补录开启、录取结果。

## 页面模块设计

### 学生端
1. **首页/公告页**：流程时间轴（当前阶段高亮）、宣讲与开放日公告、实训室列表入口；
2. **实训室详情页**：项目方向、名额、导师介绍、培养安排、考核要求；
3. **意向填报页**：3 个平行志愿选择器 + 两个调剂服从勾选 + 提交/修改；
4. **我的选拔页**（核心个人页）：当前状态机展示（已填报/面试中/拟录取/待确认/已确认/递补中/补录中/调剂中/已录取）、拟录取确认操作（含倒计时）、补轮填报入口；
5. **结果页**：最终去向、公示名单链接。

### 导师/实训室端
6. **报名学生列表页**：按轮次筛选，查看学生意向与基本信息；
7. **面试评价页**：四维度打分 + 评语，批量录入；
8. **名单管理页**：拟定拟录取/递补（可拖拽排序定顺位）/内部调剂候选三份名单并提交。

### 学院管理员端
9. **流程配置页**：8 个阶段的时间窗口设置、当前阶段切换；
10. **名额与补录管理页**：各室名额总览、剩余名额发布、开启第二/三轮补录；
11. **统筹调剂工作台**：调剂池视图、三级优先级操作面板、约谈记录录入；
12. **公示管理页**：生成最终名单、发布/结束公示、处理异议标记；
13. **数据看板**：各阶段人数统计（报名/面试/拟录取/确认/放弃/调剂/录取）。

## 设计与体验要求

- **状态清晰**：学生任何时刻打开"我的选拔页"都能一眼知道自己处于哪一步、下一步要做什么、截止时间是什么（倒计时突出显示）；
- **时间窗口强提示**：非窗口期操作入口置灰并显示开放时间；临近截止（如剩 1 小时）红色提醒；
- **规则透明**：填报页明示"平行志愿不分先后"、确认页明示"逾期视为放弃"；
- **移动端适配**：学生端以手机浏览为主，响应式布局；管理端以桌面为主；
- **视觉风格**：简洁学院风，可参考流程图的蓝绿色系；步骤条/时间轴组件贯穿始终；
- **防误操作**：提交志愿、确认去向、放弃录取等关键操作二次确认弹窗；
- **中文界面**，文案面向学生通俗易懂。

## 技术约束

- B/S 架构 Web 应用，前后端分离；
- 前端：Vue 3 或 React（小组熟悉哪个用哪个）+ 组件库（如 Element Plus / Ant Design）；用vue；
- 后端：任选小组熟悉的技术（如 Node.js/Express、Python/FastAPI、Java/Spring Boot），提供 REST API；用Java和springboot；
- 数据库：MySQL 或 SQLite（课程作业规模 SQLite 足够）；用mysql；
- 登录认证：学号/工号 + 密码，基于角色的访问控制（学生/导师/管理员）；密码要设置加密在数据库里；
- 所有时间窗口判断以**服务器时间**为准，不信任客户端时间；
- 关键操作（确认、放弃、调剂）写入操作日志，可追溯；
- 部署：本地或校园服务器可运行即可，不要求公网高可用。

## 素材与数据

- **流程依据**：选拔流程流程图（mmexport1794203798244.jpg），8 阶段时间以学院当轮配置为准；
- **基础数据**（需准备种子/模拟数据）：

  - 学生名单：学号、姓名、班级（建议 60–100 条模拟数据，覆盖满额/未满额/多意向/放弃/不服从调剂等场景）；
  - 面试评分表：四维度评分记录；
- **文案素材**：宣讲通知、开放日安排、公示模板；
- **数据字典**：选拔状态枚举（未填报/已填报/面试完成/拟录取/已确认/放弃/递补/补录轮次/调剂中/已录取/已公示）。

## 验收标准

1. **全流程可走通**：用模拟数据从宣讲公告一路走到公示入组，8 个阶段状态流转正确；
2. **意向规则**：最多 3 个平行志愿；超过 3 个被拦截；窗口外无法提交/修改；
3. **面试全覆盖**：未满额实训室的报名学生同样出现在面试名单中；
4. **确认规则**：单意向自动确认；多意向须手动选择；模拟超时后状态变"放弃"且名额按递补顺位自动补上；
5. **补录规则**：第二轮、第三轮可独立开启，剩余名额计算准确，未录取学生可重新填报；
6. **调剂优先级**：先内部调剂、再跨室调剂（仅限服从者）、最后约谈安置，顺序不可颠倒且全程留痕；
7. **公示**：公示期 1 天，公示中学生可见名单，结束后状态为正式入组；
8. **权限**：学生不能访问导师/管理员页面，导师只能操作本实训室数据；
9. **并发确认**：两名学生同时确认同一递补名额时不超录；
10. **移动端**：学生端核心页面在 375px 宽度下可正常操作。

## 暂时不做的事情

- 不做真实教务系统/统一身份认证对接（用独立账号体系）；
- 不做短信/微信/邮件通知（仅站内通知）；
- 不做在线视频面试（面试线下进行，系统只录评价）；
- 不做智能推荐/自动匹配算法（录取由导师人工决定，系统只管规则与流转）；
- 不做异议申诉的线上处理流程（公示异议线下处理，系统仅标记）；
- 不做历史年份数据归档与多届管理（先支持当届一次选拔）；
- 不做消息推送 App、小程序端。
