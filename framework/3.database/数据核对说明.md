# 数据核对说明

> 依据：《实训室选报宣讲纪要》11月2日（202/204/402/404/406/505）
> 结论：6 个实训室统一按 **64 人**核定，名额按各室导师人数分配。

---

## 一、为什么统一是 64 人

录音里有三处直接说了同一个数：

| 原文 | 出处 |
| --- | --- |
| "每间最多招收 **64** 人，由四位老师带队，每位老师负责指导约 16 人" | 402 室 |
| "每位老师负责 16 名学生，共计 **64** 个位置" | 505 室 |
| "本期总共招募 **64** 名同学" | 202 室 |

所以 **64 是全院统一的每室上限**，不是各室自己定的。凡是偏离 64 的，优先怀疑转录错误。

## 三、404 为什么从 20 改成 64

原文（404 负责人高璇介绍）：

> "高璇老师名额为 14 人，冯帆老师和张慧斌老师各为 3 人。"

**三个疑点：**

1. **漏人**：404 一共介绍了 5 位导师（高璇、张慧斌、王鹏帆、王凤佩、徐瑞泽），这句话只提了 3 位。
2. **数量级不对**："各为 3 人"与"每位老师指导约 16 人"的常规相差 5 倍。
3. **整室算不过来**：20 人 ÷ 5 位导师 = 每位 4 人。一个实训室只带 4 个人，与"每间 64 人"的统一口径矛盾。

**最可能的转录错误**：**"十三" 被听成 "三"**（漏掉"十"）。语音转写对"十三/三"这类数量词丢字非常常见，而"三"和"十三"在口语里紧挨着。

**按 64 重构：**

| 导师 | 名额 | 说明 |
| --- | --- | --- |
| 高璇（负责人） | 14 | 原文数字保留 |
| 张慧斌 | 13 | 原文"3"→ 补"十" |
| 王鹏帆 | 13 | 原文"冯帆 3"→ 同音修正 + 补"十" |
| 王凤佩 | 12 | 原文未提，按平均补 |
| 徐瑞泽 | 12 | 原文未提，按平均补 |
| **合计** | **64** | ✅ |

## 四、406 的 62 → 64（假设，随时可回退）

原文："总接纳人数上限为 **62** 人。"

62 不像明显错字，但与其他五间都 64 不一致。两种可能：

- 转录误差（62 ↔ 64 在部分地区口音里接近）
- 确实少了 2 个位置（某位老师只带 12 人）

**本次统一按 64 处理**（13+13+13+13+12）。如果确认是 62，执行：

```sql
UPDATE mentor SET quota = 13 WHERE lab_id = (SELECT id FROM lab WHERE code='406') AND name IN ('杨振英','马庆宇');
UPDATE mentor SET quota = 12 WHERE lab_id = (SELECT id FROM lab WHERE code='406') AND name IN ('戴一凡','庞凯文','丁文雷');
UPDATE lab SET quota = 62 WHERE code = '406';
```

## 七、名额一致性校验

改完数据后跑一次，每个室都应显示 `OK`：

```sql
SELECT l.code,
       l.name,
       l.quota              AS 室总名额,
       SUM(m.quota)         AS 导师名额合计,
       CASE WHEN l.quota = SUM(m.quota) THEN 'OK' ELSE '不一致' END AS 结果
  FROM lab l
  LEFT JOIN mentor m ON m.lab_id = l.id
 GROUP BY l.id
 ORDER BY l.code;
```

## 八、业务规则复核（对照录音原文）

| 规则 | 录音原文 | 系统落点 |
| --- | --- | --- |
| 最多 3 个导师意向 | "可填报 3 个导师" | `application_item` 最多 3 条 |
| 意向不分先后 | "不区分先后顺序" | 无优先级字段，只有 `sort_no` 展示序 |
| 两个调剂意愿 | "是否服从实训室内部调剂或全院跨实训室调剂" | `adjust_in_lab` / `adjust_cross` 两个独立字段 |
| 双向选择 | "学生主动选老师，老师通过面试筛选学生" | 意向（学生侧）+ 面试评分与名单（导师侧） |
| 面试评估 | "老师会组织面试以评估匹配度" | `interview_score` 四维度 |
| 仅 1 个意向 → 直接确定 | "若只收到一个老师意向，选报即完成" | offer 单条 → 自动 `CONFIRMED` |
| ≥2 个意向 → 学生自选 | "若收到两个以上老师意向，学生可在其中选择一个" | 限时确认，选一弃余 |
| 多轮补录 | "组织第二轮、第三轮选报及调剂" | `round_no` 1/2/3 |
| 全员有组 | "最终目标是保证大家都有实验室和相应的指导老师" | 三级调剂兜底（室内 → 跨室 → 约谈） |
| 名额在导师 | "高璇 14 人、张慧斌 3 人" | `mentor.quota` |

**结论：现有表结构与接口设计能覆盖以上全部规则，无需改结构，只需要把数据改对。**
