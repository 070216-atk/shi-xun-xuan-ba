## 0. 通用约定

**统一响应**

```json
{ "code": 0, "message": "ok", "data": {} }
```

**分页响应**（`data` 部分）

```json
{ "list": [], "total": 0, "page": 1, "size": 20 }
```

**约定**

- 主键统一为**数字** `id`；`L1` 这类展示编号放 `code` 字段（前端 mock 里的 `id: 'L1'` 需要改）
- 时间统一 `yyyy-MM-dd HH:mm:ss`，时区 `Asia/Shanghai`
- 角色枚举大写：`STUDENT` / `TEACHER` / `ADMIN`
- 轮次 `round`：1 首轮 / 2 第二轮 / 3 第三轮

## 1. 认证

### POST /api/auth/login

请求
```json
{ "username": "student01", "password": "123456" }
```

响应
```json
{ "code": 0, "message": "ok", "data": {
  "token": "eyJhbGciOiJIUzI1NiJ9...",
  "expiresIn": 7200,
  "user": {
    "id": 4, "username": "student01", "role": "STUDENT",
    "code": "S2023001", "realName": "李明",
    "className": "计科2301", "labId": null, "mentorId": null
  }
}}
```

> `className` 学生才有；`labId` / `mentorId` 导师才有。

### GET /api/auth/me
返回上面的 `user` 对象。

### POST /api/auth/logout
无请求体，返回 `data: null`（JWT 无状态，前端丢弃 token 即可；此接口仅写日志）。

## 2. 公开信息

### GET /api/stages

```json
{ "code": 0, "message": "ok", "data": [
  { "id": 3, "stageNo": 3, "round": 1, "name": "意向填报",
    "startAt": "2026-11-02 08:00:00", "endAt": "2026-11-02 12:00:00",
    "open": true, "isCurrent": true, "remainingSeconds": 14400,
    "description": "最多填报 3 个平行导师意向，不分先后" }
]}
```

> **与前端 mock 的差异**：mock 里是 `window: "11月2日 08:00–12:00"` 这种展示字符串。
> 后端必须给 `startAt` / `endAt` / `remainingSeconds`，**格式化由前端做**。
> `remainingSeconds` 只是展示用，服务端仍以自己时间判断放行。

### GET /api/labs

```json
{ "data": [
  { "id": 1, "code": "L1", "name": "智能软件系统实训室",
    "direction": "AI 应用开发、全栈工程、智能软件系统设计",
    "quota": 12, "applied": 5, "mentorCount": 2 }
]}
```

> `applied` = 已报名人数（沿用 mock 的命名）。
> **待确认**：是否对外暴露实时报名人数（可能引发从众），建议只给区间或干脆不给。

### GET /api/labs/{id}

```json
{ "data": {
  "id": 1, "code": "L1", "name": "智能软件系统实训室",
  "direction": "...", "training": "...", "assessment": "...",
  "location": "实验楼 A301", "contact": "张建国 138-0000-0001",
  "openDay": "10月29日 15:30 / 10月30日 09:00",
  "quota": 12, "applied": 5,
  "mentors": [ { "id": 1, "name": "张建国", "title": "副教授", "intro": "..." } ]
}}
```

## 3. 学生端

### GET /api/student/application?round=1

未填报时 `data: null`。

```json
{ "data": {
  "round": 1,
  "adjustInLab": true,
  "adjustCross": false,
  "status": "SUBMITTED",
  "submittedAt": "2026-11-02 08:30:12",
  "items": [
    { "labId": 1, "labCode": "L1", "labName": "智能软件系统实训室", "mentorId": 1, "mentorName": "张建国" },
    { "labId": 2, "labCode": "L2", "labName": "大数据与云计算实训室", "mentorId": 3, "mentorName": "王志强" }
  ]
}}
```

### PUT /api/student/application

请求
```json
{ "round": 1,
  "items": [
    { "labId": 1, "mentorId": 1 },
    { "labId": 2, "mentorId": 3 }
  ],
  "adjustInLab": true,
  "adjustCross": true }
```

校验（全部在 service 层）
| 规则 | 错误码 |
| --- | --- |
| 1–3 条 | `2002` 志愿数超限 |
| 同一实训室可填多位导师（只限制同一位导师不重复） | — |
| `mentorId` 不重复 | `2002` |
| 当前处于填报窗口 | `2001` 不在时间窗口 |

> 同一学生同一 `round` 重复 PUT = 覆盖（先删 items 再插），不是报错。

### GET /api/student/status

```json
{ "data": {
  "round": 1,
  "status": "OFFERED",
  "statusText": "已获得拟录取，请在截止前选择唯一去向",
  "currentStage": 5,
  "currentStageName": "拟录取与学生确认",
  "deadline": "2026-11-04 12:00:00",
  "remainingSeconds": 7200
}}
```

`status` 取值：`NOT_APPLIED` `APPLIED` `INTERVIEWED` `OFFERED` `CONFIRMED` `DECLINED` `WAITLISTED` `ADJUSTING` `NOT_ADMITTED` `ADMITTED`

### GET /api/student/offers

```json
{ "data": [
  { "offerId": 10, "labId": 1, "labCode": "L1", "labName": "智能软件系统实训室",
    "mentorId": 1, "mentorName": "张建国",
    "type": "ADMITTED", "status": "ISSUED",
    "confirmDeadline": "2026-11-04 12:00:00", "remainingSeconds": 3600 }
]}
```

`type`：`ADMITTED` 拟录取 / `WAITLIST` 递补 / `ADJUST_CANDIDATE` 调剂候选
`status`：`ISSUED` `CONFIRMED` `DECLINED` `EXPIRED` `VOID`

### POST /api/student/offers/{offerId}/confirm

无请求体。

```json
{ "code": 0, "message": "ok", "data": { "confirmedLabId": 1, "releasedCount": 2 } }
```

> 用 `labId` 定位是安全的：`offer` 表有唯一键 `(student_id, round_no, lab_id)`，
> 一个学生一轮内对同一导师最多一个意向。
> 执行时必须 **事务 + `SELECT ... FOR UPDATE`** 锁 `mentor` 行，否则并发确认会超录。

## 4. 导师端

### GET /api/teacher/applicants?round=1

```json
{ "data": [
  { "studentId": 4, "code": "S2023001", "realName": "李明", "className": "计科2301",
    "preferredMentorId": 1, "preferredMentorName": "张建国",
    "adjustInLab": true, "adjustCross": false,
    "interviewed": false,
    "scores": null }
]}
```

已评分的 `scores`：
```json
{ "attitude": 4, "logic": 3, "coding": 2, "time": 5, "total": 3.5, "comment": "基础偏弱，投入度高" }
```

> 无论报名是否满额，**本室所有报名学生都必须出现在这个列表里**（PRD R4）。

### PUT /api/teacher/scores/{studentId}

```json
{ "round": 1, "attitude": 4, "logic": 3, "coding": 2, "time": 5, "comment": "..." }
```

四个维度都是 1–5 的整数，缺一个返回 `400`。

### GET /api/teacher/lists?round=1

```json
{ "data": {
  "round": 1, "quota": 12,
  "admitted": [ { "studentId": 4, "realName": "李明", "mentorId": 1, "total": 4.5 } ],
  "waitlist": [ { "studentId": 5, "realName": "王芳", "mentorId": 1, "rank": 1, "total": 4.0 } ],
  "adjustCandidates": []
}}
```

### PUT /api/teacher/lists

```json
{ "round": 1,
  "admitted": [4, 7],
  "waitlist": [5, 6],
  "adjustCandidates": [8] }
```

校验：`admitted` 数量 ≤ `quota`，否则 `2003` 名额已满。

## 5. 管理员端（字段简表）

| 接口 | 关键字段 |
| --- | --- |
| `PUT /admin/stages/{id}` | `startAt`、`endAt`（都必填） |
| `GET /admin/quotas` | `[{ labId, labName, quota, applied, admitted, remaining }]` |
| `POST /admin/rounds` | `{ "round": 2 }`，校验上一轮已 `CLOSED` |
| `POST /admin/quotas/publish` | `{ "round": 2 }` |

| `POST /admin/adjust/internal` | `{ "labId":1, "studentIds":[5] }` |
| `POST /admin/adjust/cross` | `{ "labId":2, "studentIds":[6] }` |
| `POST /admin/adjust/talk` | `{ "studentId":9, "labId":3, "conclusion":"同意安置" }` |

## 6. 错误码

| code | 含义 |
| --- | --- |
| 0 | 成功 |
| 1001 | 未登录 / token 无效 |
| 1002 | 用户名或密码错误 |
| 1003 | 无权限（角色不符或跨实训室操作） |
| 2001 | 不在时间窗口 |
| 2002 | 志愿数超限 / 重复 |
| 2003 | 名额已满 |
| 2004 | 调剂优先级顺序错误 |
| 2005 | 存在未处理异议 |
| 5000 | 服务器内部错误 |

## 7. 与前端 mock 的差异清单（必须同步给前端）

| mock 现状 | 应改为 | 影响 |
| --- | --- | --- |
| `lab.id: 'L1'` | `id: 1` + `code: 'L1'` | 路由参数、表单值 |
| `stage.window: '11月2日 08:00–12:00'` | `startAt` / `endAt` / `remainingSeconds` | 时间轴组件要重写格式化 |
| `mentors[].{name,title,intro}` 无 id | 加 `id` | 意向填报要提交 `mentorId` |
| `role: 'student'` 小写 | `'STUDENT'` | 路由守卫判断 |
| `users[].password` 明文 | 后端不返回密码字段 | 登录接口 |

## 8. v0.2 变更说明（依据真实宣讲数据）

宣讲纪要里 404 室明确到"高璇 14 人、张慧斌 3 人"，说明**名额是按导师分配的**，
原设计"名额挂实训室、按 labId 确认"不成立。改动如下：

| 项 | v0.1 | v0.2 |
| --- | --- | --- |
| 名额归属 | lab.quota | **mentor.quota**（lab.quota 退化为汇总展示） |
| 意向必填 | labId + 可选 mentorId | **mentorId 必填**（lab 由 mentor 推出） |
| offer 唯一键 | (student_id, round_no, lab_id) | **(student_id, round_no, mentor_id)** |
| 确认接口 | POST /student/offers/{labId}/confirm | **POST /student/offers/{offerId}/confirm** |
| 并发控制 | 锁 lab 行 | 锁 mentor 行 |

改动理由：同一实训室有多个导师时，用 labId 定位 offer 会产生歧义；用 offerId（主键）则天然唯一。
